4. Preserve no-extra-stack-traversal behavior.
5. Do not recompute the entire stack solely for reconstruction.
6. If exact invertibility causes cancellation for a parameter group, document the proven result rather than fabricating a signal.
7. If finite-precision reconstruction is intentionally used as a stability signal, bound and test it.
8. Ensure reconstruction scaling is independent of padding.
9. Ensure `reconstruction_alpha` phases change the intended gradient rather than only a reported metric.

Log-determinant signal:

1. Preserve O(dim) triangular-Jacobian computation.
2. Validate sign and scale.
3. Ensure `logdet_weight` reaches the intended scale-path derivative.
4. Test zero weight equivalence against ordinary backward.
5. Test nonzero weight changes only the mathematically expected adjoint terms.

Embedding gradient:

1. Accumulate embedding gradients in f32.
2. Do not use f16 histogram accumulation for repeated tokens.
3. Exclude padding and invalid tokens.
4. Use a verified global norm or token-normalized scale.
5. If distributed, apply local token weighting exactly once.
6. Perform NCCL reduction in f32.
7. Zero the gradient state only after a successful update.
8. On update failure, retain gradients and state for diagnostic handling or abort safely.

Learning rate:

- Remove the benchmark default `0.005` unless validated under the repaired normalization.
- Start validation at `3e-4`.
- Add warmup if enabled.
- Record actual update-to-weight ratios.
- Select the final default from measured stable runs, not guesswork.

Make spectral stabilization consistent with the documented production behavior.

Current CPU-side spectral constraints do not automatically constrain the live GPU coupling stack.

Implement:

1. Per-layer GPU spectral-state arrays for S and T, or another bounded-memory equivalent.
2. Power iteration on f32 master coupling weights.
3. Configurable target norm.
4. Configurable power-iteration count.
5. A configurable application interval.

8. No full GPU→CPU weight transfer for routine normalization.
9. No reset of SFD momentum/Fisher when weights are spectrally rescaled.
10. If weights are rescaled, define whether momentum/Fisher should be rescaled consistently; implement and test the chosen invariant.

Embedding spectral normalization:

- operate on the f32 master embedding;
- regenerate the f16 shadow afterward;
- do not repeatedly shrink the whole matrix due to an incorrect target hardcoded to 1.0 when config requests 0.9;
- use the configured target singular value;
- separate estimation from normalization;

Remove duplicate CPU/GPU spectral implementations or make one a tested reference.

──────────────────────────────────────────────────────────────────────────────
PHASE 11 — RSF FUTHARK KERNEL PERFORMANCE
──────────────────────────────────────────────────────────────────────────────

Optimize the existing RSF equations without changing the architecture.

The current per-row/per-token scalar reductions and materialized per-token outer products must be replaced with token-major, matrix-shaped computations.

For each layer, flatten active batch/sequence rows into M active tokens.

Forward:

1. Split:
   X1: [M][half]
   X2: [M][half]

2. Separate weights:
   Ws_body: [half][half]
   bs: [half]
   Wt_body: [half][half]
   bt: [half]

3. Compute:
   P = X2 · transpose(Ws_body) + bs

4. Clamp:
   S = clamp(P, clip_min, clip_max)

5. Scale:
   Y1 = X1 ⊙ exp(S)

6. Translation:
   T = Y1 · transpose(Wt_body) + bt

7. Coupling:
   Y2 = X2 + T

8. OFTB:
   apply the existing reversible mixing.

Backward for each layer in reverse order:

1. Undo OFTB on outputs and adjoints.
2. Reconstruct X2 and X1 algebraically.
3. Compute:
   dY1_total = dY1 + dY2 · Wt_body

4. Compute scale adjoint with clipping mask and log-determinant term.
5. Compute:
   dX1 = dY1_total ⊙ exp(S)

6. Compute:
   dX2 = dY2 + dS · Ws_body

7. Parameter gradients:
   dWs_body = transpose(dS) · X2
   dbs = reduce_rows(dS)
   dWt_body = transpose(dY2) · Y1
   dbt = reduce_rows(dY2)

8. Use f32 accumulation for every reduction.
9. Apply the canonical SFD update to f32 masters.
10. Convert updated masters to f16 shadows.

Do not materialize `[token][half][half+1]` parameter-gradient matrices.

Do not construct one full outer-product matrix per token and then reduce it.

Padding compaction:

1. Build active-token indices from sequence lengths.
2. Gather active input and target rows.
3. Run the RSF stack only over active rows.
4. Scatter input deltas back into the padded 3D layout.
5. Ensure padding rows remain exactly zero where required.
6. Avoid processing the full `batch × max_seq_len` when actual lengths are shorter.
7. The compaction operation must remain on GPU after lengths are uploaded.

Futhark implementation:

- use shape-specialized, tiled, fusion-friendly array operations;
- avoid repeated full transposes inside inner loops when transposed views or prepacked layouts can be maintained;
- evaluate whether storing weight bodies in the orientation consumed by forward/backward removes transposes;
- preserve exact bias handling;
- do not introduce cuBLAS or an external ML dependency;
- inspect generated CUDA to verify the resulting kernels are not scalar per-row reductions;
- record achieved throughput and HBM bandwidth;
- distinguish Futhark compile limitations from architecture limitations.

Kernel tests:

- forward equivalence against current reference;
- inverse equivalence;
- backward input-gradient equivalence;
- S/T parameter-gradient equivalence;
- log-determinant equivalence;
- reconstruction equivalence;
- padding equivalence;
- one-layer and multilayer tests;
- tolerances appropriate to f16 shadows with f32 accumulation.

7. Persist all tokenizer state required for exact resume.

Graph chunk boundaries:

The graph kernel produces predecessor relations up to distance three. Chunked graph encoding must preserve relations crossing chunk boundaries.

Implement one of:

A. Three-element overlap:
   - for every chunk after the first, include the previous three nodes;
   - discard duplicate node outputs;
   - retain cross-boundary edges and bitmask bits.

or:

B. Postprocess boundary edges:
   - generate missing predecessor relations explicitly from global indices.

Verify:

- edge from chunk_start to chunk_start−1;
- edge to chunk_start−2;
- edge to chunk_start−3;
- no duplicate edges;
- correct global index offset.

Graph bitmask memory:

1. Calculate the full bitmask memory before allocation.
2. Do not allocate an O(n²/64) global bitmask for 500,000 nodes unless the live algorithm actually requires and can efficiently consume it.
3. Use sparse/chunked bitmask shards if graph locality is bounded.
4. Do not copy a multi-gigabyte global bitmask unnecessarily between host and device.
5. Preserve sparse self-similar relations.
6. Measure graph construction and propagation separately from training.

Relational pass:

1. Measure its actual cost.
2. Do not run CPU-heavy graph mutation synchronously every ten steps without profiling.
3. Preserve relational behavior, but move non-weight-dependent bookkeeping off the GPU critical path where safe.
4. Define state ownership if moved to a worker.
5. Ensure the pass uses completed step data.
6. Preserve deterministic ordering where checkpoint/resume requires it.
7. Restore the default interval only after measurement; do not blindly assume 10 or 50 is correct.
8. Include relational-pass time in step telemetry.

──────────────────────────────────────────────────────────────────────────────
PHASE 13 — REMOVE OR QUARANTINE NON-PRODUCTION IMPLEMENTATIONS
──────────────────────────────────────────────────────────────────────────────

Audit the following components and either implement them completely in the live production path or remove them from production compilation behind an explicit experimental build option.

1. Simulated precision
   - `Tensor` stores `[]f32` regardless of declared FP4/FP8/FP16 dtype.
   - Quantizing values in an f32 buffer is not physical low-precision storage.
   - Do not label it memory compression.
   - Either implement packed physical storage and live kernels or quarantine/delete it.

2. `B200MemoryManager`
   - A host byte array is not B200 Tensor Memory.
   - A one-way copy with an `in_tensor_memory` flag is not device placement.
   - An unconsumed prefetch queue is not prefetching.
   - Remove these claims and code from production unless implemented with real CUDA/device facilities.

3. `ReversibleOptimizerState`
   - Fabricated residual functions and gradient scaling unrelated to RSF are prohibited.
   - A cache that is never populated must not be presented as functional.
   - Replace it with real RSF inverse/backward integration or remove it.

4. `SophiaSOAPOptimizer`
   - `gradient × Rademacher vector` is not a Hessian-vector product.
   - Do not present it as Hutchinson Hessian estimation.
   - Implement a real HVP against the live objective or remove the path.
   - Do not apply two separate parameter updates from the same gradient in one call unless the combined algorithm is formally defined and tested.

5. `KFACBlock`
   - A matrix inverse is not an inverse square root.
   - Rename operations accurately or implement a real inverse square root.
   - Do not apply arbitrary modulo-index diagonal scaling as a generic fallback.
   - If KFAC is not connected to RSF production training, quarantine it.

6. Mixed precision trainer
   - Loss scaling must be applied before backward.
   - Overflow must be checked on scaled gradients.
   - On overflow, skip the complete optimizer update.
   - Back off the scale.
   - On success, unscale once and update f32 masters.
   - If this is not integrated, remove it from production.

7. Scheduler, Gaussian process, Bayesian optimizer, MARS
   - Wire each retained component into a documented production path and test it.
   - Otherwise quarantine it.
   - Do not retain unused configuration fields that imply functionality.

8. Telemetry
   - Do not report tensor-core or NVLink utilization as zero when unavailable.
   - Preserve optional/null semantics.
   - Remove average fields that convert “not measured” into fabricated zero.
   - If real counters are implemented, use a supported management API and document availability.
   - Do not invoke `nvidia-smi` as a subprocess every training step.
   - Rate-limit telemetry outside the critical path.

9. Validation metrics
   - Remove validation-loss storage if no validation pass exists.
   - Alternatively implement an actual validation pass.

10. B200 configuration constants
    - Remove decorative bandwidth/cache/TMEM values that do not affect implementation.
    - Keep only measured or actively used fields.

No production source file may contain a claim that is not backed by a live implementation.
